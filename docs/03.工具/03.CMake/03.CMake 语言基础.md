# 步骤 2：CMake 语言基础

在前面的步骤中，我们快速通过了 CMakeLists.txt 中使用的 CMake 语言的几个方面，以便尽快获得有用的、可构建的程序。然而，在实际中，我们遇到的复杂度远不止描述源文件和头文件列表这么简单。

为了处理这种复杂性，CMake 提供了一个图灵完备的领域特定语言来描述构建软件的过程。随着我们编写更复杂的 CML 和其他 CMake 文件，理解这门语言的基础知识将是必要的。这门语言正式称为"CMake 语言"，或更通俗地称为 CMakeLang。

> **注意** CMake 语言并不适合描述与构建软件无关的内容。虽然它有一些通用功能的特性，但开发者在使用 CMake 语言解决与其构建不直接相关的问题时应谨慎。
>
> 通常正确的做法是用通用编程语言编写解决该问题的工具，并教 CMake 如何在构建过程中调用该工具。已经有人用 CMake 语言编写过代码生成器、加密签名工具，甚至是光线追踪器，但这不是推荐的做法。

由于我们要充分探索语言特性，本步骤是教程顺序的例外。它既不基于步骤 1，也不是步骤 3 的起点。这将是一个沙箱环境，用于在不构建任何软件的情况下探索语言特性。我们将在步骤 3 重新开始使用 Tutorial 程序。

> **注意** 本教程致力于展示最佳实践和真实问题的解决方案。然而，对于这个步骤，我们将重新实现一些内置的 CMake 函数。在"现实生活中"，不要编写自己的 list(APPEND)。

## 背景

CMakeLang 中唯一的基本类型是字符串和列表。CMake 中的每个对象都是字符串，列表本身就是包含分号作为分隔符的字符串。任何看似操作字符串以外内容的命令（无论是布尔值、数字、JSON 对象还是其他），实际上都在消费一个字符串，执行一些内部转换逻辑（用 CMakeLang 以外的语言），然后将结果转换回字符串用于任何潜在输出。

我们可以使用 `set()` 命令创建一个变量，即字符串的名称。

```cmake
set(var "World!")

可以使用大括号展开来访问变量的值，例如如果我们想使用 `message()` 命令来打印 var 命名的字符串。

```cmake
set(var "World!")
message("Hello ${var}")
```

```bash
cmake -P CMakeLists.txt
Hello World!
```

> **注意** `cmake -P` 被称为"脚本模式"，它告知 CMake 此文件不包含 `project()` 命令。我们不构建任何软件，而是仅将 CMake 用作命令解释器。

因为 CMakeLang 只有字符串，条件语句完全依赖于哪些字符串被视为真、哪些被视为假的约定。这些应该是直观的，"True"、"On"、"Yes"和（表示）非零数字的字符串为真，而"False"、"Off"、"No"、"0"、"Ignore"、"NotFound"和空字符串都被视为假。

然而，有些规则比这更复杂，所以花一些时间查阅 `if()` 文档关于表达式的说明是值得的。建议在同一上下文中坚持使用一对，例如"True"/"False"或"On"/"Off"。

如前所述，列表是包含分号的字符串。`list()` 命令对于操作这些很有用，CMake 中的许多结构都期望以这种约定进行操作。作为一个例子，我们可以使用 `foreach()` 命令来迭代列表。

```cmake
set(stooges "Moe;Larry")
list(APPEND stooges "Curly")

message("Stooges contains: ${stooges}")

foreach(stooge IN LISTS stooges)
  message("Hello, ${stooge}")
endforeach()
```

```bash
cmake -P CMakeLists.txt
Stooges contains: Moe;Larry;Curly
Hello, Moe
Hello, Larry
Hello, Curly
```

## 练习 1 - 宏、函数与列表

CMake 允许我们创建自己的函数和宏。这在构建大量相似目标（如测试）时非常有用，因为我们希望一次又一次地调用相似的命令集合。我们通过 `function()` 和 `macro()` 来实现这一点。

```cmake
macro(MyMacro MacroArgument)
  message("${MacroArgument}\n\t\tFrom Macro")
endmacro()

function(MyFunc FuncArgument)
  MyMacro("${FuncArgument}\n\tFrom Function")
endfunction()

MyFunc("From TopLevel")
```

```bash
cmake -P CMakeLists.txt
From TopLevel
      From Function
              From Macro
```

与许多语言一样，函数和宏之间的区别在于作用域。在 CMakeLang 中，`function()` 和 `macro()` 都可以"看到"它们上方所有帧中创建的所有变量。然而，`macro()` 在语义上类似于文本替换，类似于 C/C++ 宏，因此宏创建的任何副作用在调用上下文中都是可见的。如果我们在宏中创建或修改变量，调用者将看到该更改。

`function()` 创建自己的变量作用域，因此副作用对调用者不可见。为了将更改传播到调用函数的父级，我们必须使用 `set(<var> <value> PARENT_SCOPE)`，其工作方式与 `set()` 相同，但针对属于调用者上下文的变量。

> **注意** 在 CMake 3.25 中，添加了 `return(PROPAGATE)` 选项，其工作方式与 `set(PARENT_SCOPE)` 相同，但提供了稍微更好的易用性。

虽然本练习中不需要，但值得一提的是，`macro()` 和 `function()` 都通过 `ARGV` 变量支持可变参数，这是一个包含传递给命令的所有参数的列表，以及 `ARGN` 变量，包含最后一个预期参数之后的所有参数。

我们不会在本练习中构建任何目标，因此我们将构建自己的 `list(APPEND)` 版本，它向列表添加一个值。

## 练习 2 - 条件与循环

在任何结构化编程语言中，两种最常见的流程控制元素是条件语句和它们 close sibling 循环。CMakeLang 也不例外。如前所述，给定 CMake 字符串的真值是由 `if()` 命令建立的约定。

当给定一个字符串时，`if()` 首先检查它是否是之前讨论的已知常量值之一。如果字符串不是这些值之一，该命令假设它是一个变量，并检查该变量大括号展开的内容以确定条件语句的结果。

```cmake
if(True)
  message("Constant Value: True")
else()
  message("Constant Value: False")
endif()

if(ConditionalValue)
  message("Undefined Variable: True")
else()
  message("Undefined Variable: False")
endif()

set(ConditionalValue True)

if(ConditionalValue)
  message("Defined Variable: True")
else()
  message("Defined Variable: False")
endif()
```

```bash
cmake -P ConditionalValue.cmake
Constant Value: True
Undefined Variable: False
Defined Variable: True
```

> **注意** 现在是讨论 CMake 中引用的好时机。CMake 中的所有对象都是字符串，因此双引号 `"` 通常是不必要的。CMake 知道该对象是一个字符串，一切都是字符串。
>
> 然而，它在某些上下文中是必要的。包含空格的字符串需要双引号，否则它们被视为列表；CMake 会将元素用分号连接起来。反过来也是如此，当展开列表时，如果我们要保留分号，则必须在引号内进行展开。否则 CMake 会将列表项展开为空格分隔的字符串。

少数命令，如 `if()`，能够区分带引号和不带引号的字符串。`if()` 仅在字符串未加引号时才会检查给定字符串是否表示变量。

最后，`if()` 提供了几个有用的比较模式，例如用于字符串匹配的 STREQUAL、用于检查变量存在的 DEFINED，以及用于正则表达式检查的 MATCHES。它还支持典型的逻辑运算符 NOT、AND 和 OR。

除了条件语句外，CMake 还提供了两种循环结构，`while()` 遵循与 `if()` 相同的规则来检查循环变量，以及更有用的 `foreach()`，它迭代字符串列表，在背景部分已演示过。

对于本练习，我们将使用循环和条件语句来解决一些简单的问题。我们将使用前述的 `ARGN` 变量（来自 `function()`）作为要操作的列表。

## 练习 3 - 使用 Include 组织代码

我们已经讨论了如何使用 `add_subdirectory()` 合并包含它们自己的 CML 的子目录。在后面的步骤中，我们将探索 CMake 代码可以打包和跨项目共享的各种方式。

然而，对于小型 CMake 函数和工具，让它们存在于项目 CML 之外的独立 .cmake 文件中，并与构建系统其余部分分开，通常是有益的。这允许关注点分离，从我们用来描述它们的工具中移除项目特定的元素。

为了将这些独立的 .cmake 文件合并到我们的项目中，我们使用 `include()` 命令。此命令立即在父 CML 的作用域内开始解释被 include 文件的内容。就好像整个文件都被作为宏调用一样。

传统上，这类 .cmake 文件存在于项目根目录内名为"cmake"的文件夹中。对于本练习，我们将使用 Step2 文件夹。
