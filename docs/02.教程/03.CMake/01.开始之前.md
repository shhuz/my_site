# 步骤 0：开始之前

CMake 教程包含动手实践练习，通过编写和构建 C++ 项目来解决越来越复杂的构建需求，例如库、代码生成器、测试和外部依赖项。在我们准备好开始这段旅程的第一步之前，需要确保手头有正确的工具并了解如何使用它们。

> **注意** 本教程假定用户具备 C++20 编译器和工具链，并对 C++ 语言有初学者级别的理解。此处无法涵盖获取这些先决条件的所有可能方式。

本先决条件步骤提供有关如何获取和运行 CMake 以完成教程其余部分的建议。如果您已经熟悉运行 CMake 的基本知识，可以自由跳到教程的其余部分。

## 获取 CMake

获取 CMake 最直接的方式是从 CMake 网站下载。网站上的"下载"部分包含适用于所有常见（和一些不常见）桌面平台的最新 CMake 构建版本。

然而，更推荐通过平台上的开发者工具常规交付机制获取 CMake。CMake 在大多数软件包仓库中可用，可作为 Visual Studio 组件安装，甚至可以从 Python 软件包索引安装。此外，CMake 通常也可作为针对 C/C++ 的大多数 CI/CD 运行程序基础镜像的一部分。请查阅软件构建环境的文档以确认 CMake 是否已可用。

CMake 也可以使用在 CMake 源码树根目录下的 README.rst 中描述的说明从源码编译。

像任何程序一样，CMake 需要位于 PATH 中才能从 shell 运行。您可以通过运行任意 CMake 命令来验证 CMake 是否可用：

```bash
$ cmake --version
cmake version 3.23.5

CMake suite maintained and supported by Kitware (kitware.com/cmake).
```

> **注意** 如果使用 Visual Studio 提供的开发环境，最好在开发者命令提示符或开发者 PowerShell 中运行 CMake。这可以确保 CMake 能够访问所有必需的开发者工具和变量。

## CMake 生成器

CMake 是一个配置程序，有时被称为"元"构建系统。与其他配置系统一样，CMake 并不直接负责运行产生软件构建的命令。相反，CMake 会根据项目、环境和用户提供的配置信息生成一个构建系统。

CMake 支持多种构建系统作为此配置过程的输出。这些输出后端称为"生成器"，因为它们生成构建系统。CMake 支持许多生成器，相关文档可在 cmake-generators(7) 中找到。有关您特定 CMake 安装的支持生成器信息，可通过 `cmake --help` 在"Generators"标题下查看。

因此，使用 CMake 需要能够消费此生成器输出的构建程序可用。Unix Makefiles、Ninja 和 Visual Studio 生成器分别需要兼容的 make、ninja 和 Visual Studio 安装。

> **注意** Windows 上的默认生成器通常是机器上可用的最新 Visual Studio 版本，其他平台默认是 Unix Makefiles。

可以使用 `CMAKE_GENERATOR` 环境变量或 `cmake -G` 选项来控制使用哪个生成器。

## 单配置与多配置生成器

在许多情况下，可以将底层构建系统视为实现细节，在使用 CMake 时不必区分 ninja 和 make。但是，对于甚至是最简单的 workflows，我们需要注意给定生成器的一个重要属性：该生成器是否支持单配置构建或多配置构建。

软件构建通常有多个变体，我们可能对此感兴趣。这些变体有诸如 Debug、Release、RelWithDebInfo 和 MinSizeRel 等名称，具有与给定变体名称对应的属性。

单配置构建系统始终以相同的方式构建软件——如果生成的是 Debug 构建，则始终产生 Debug 构建。多配置构建系统可以根据构建时指定的配置产生不同的输出。

> **注意** 术语"构建配置"和"构建类型"是同义词。在处理仅支持单个变体的单配置生成器时，生成的变体通常称为"构建类型"。在处理多配置生成器时，可用的变体通常称为"构建配置"。在构建时选择变体通常称为"选择配置"，并通过标志和变量引用为"config"。

然而，这种约定并非普遍适用。技术文档和通俗文档经常混用这两个术语。在同时涉及单配置和多配置生成器的上下文中，"配置"和"config"被认为更准确。

常用的生成器如下：

| 单配置 | 多配置 |
|--------|--------|
| Ninja | Ninja Multi-Config |
| Unix Makefiles | Visual Studio (所有版本) |
| | FASTBuild |
| | Xcode |

使用单配置生成器时，构建类型基于 `CMAKE_BUILD_TYPE` 环境变量选择，或通过 `cmake -DCMAKE_BUILD_TYPE=<config>` 在调用 CMake 时直接指定。

> **注意** 就本教程而言，在使用单配置生成器时通常无需指定构建类型。平台特定的默认行为将适用于所有练习。

使用多配置生成器时，构建配置在构建时指定，可以使用构建系统特定的机制，或通过 `cmake --build --config` 选项指定。

## 其他使用基础

教程其余部分将更深入地介绍剩余的使用基础，但为了确保我们有可用的开发环境，此处将枚举几个 CMake 选项标志。

- `cmake -S <dir>`：指定项目根目录，CMake 将在此处找到要构建的项目。其中包含根 CMakeLists.txt 文件，将在教程步骤 1 中讨论。未指定时默认为当前工作目录。

- `cmake -B <dir>`：指定构建目录，CMake 将在其中输出生成构建系统的文件，以及运行构建系统时的构建产物。未指定时默认为当前工作目录。

- `cmake --build <dir>`：在指定构建目录中运行构建系统。这是对所有人所有生成器通用的命令。对于多配置生成器，可通过以下方式请求所需配置：

```bash
cmake --build <dir> --config <cfg>
```

## 试用

Help/guide/tutorial/Step0 目录包含一个简单的"Hello World" C++ 项目。CMake 配置此项目的具体内容将在教程步骤 1 中讨论，我们只需关注运行 CMake 程序本身。

如上所述，根据我们要使用的生成器类型，我们可能有多种运行 CMake 的方式。如果我们导航到 Help/guide/tutorial/Step0 目录并运行：

```bash
cmake -B build
```

CMake 将使用平台的默认生成器，为 Step0 项目生成构建系统到 Help/guide/tutorial/Step0/build。或者我们可以指定特定的生成器，例如 Ninja：

```bash
cmake -G Ninja -B build
```

效果类似，但将使用 Ninja 生成器而不是平台默认生成器。

> **注意** 我们不能用不同的生成器重用构建目录。如果要用相同的构建目录切换到不同的生成器，需要在每次 CMake 运行之间删除 build 目录。

生成构建系统后如何构建和运行项目取决于我们使用的生成器类型。如果是在非 Windows 平台上的单配置生成器，我们可以简单地执行：

```bash
cmake --build build
./build/hello
```

> **注意** 在 Windows 上，我们可能需要根据所使用的 shell 指定文件扩展名，即 `./build/hello.exe`

如果我们使用多配置生成器，我们将需要指定构建配置。默认配置是 Debug、Release、RelWithDebInfo 和 MinSizeRel。构建结果将存储在构建文件夹中特定配置的子目录下。例如我们可以运行：

```bash
cmake --build build --config Debug
./build/Debug/hello
```
