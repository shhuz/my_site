# 步骤 9：安装命令与概念

项目需要做的不仅仅是构建和测试代码。它们需要使其可供使用者使用。构建树中的文件布局不适合其他项目使用。二进制文件位于意外位置，头文件位于源树中很远的地方，而且没有明确的方法发现提供了哪些目标或如何使用它们。

将产物从源树和构建树移动到位适合消费的最终布局称为安装。CMake 支持作为项目描述一部分的完整安装工作流，控制构建树中产物的布局以及为想要消费安装树提供的库的其他 CMake 项目重建目标。

## 背景

所有 CMake 安装都通过单个 `install()` 命令进行，该命令分为许多负责安装过程各个方面的子命令。对于基于目标 CMake 工作流，主要依赖于使用 `install(TARGETS)` 安装目标本身，而不是诉诸使用 `install(FILES)` 或 `install(DIRECTORY)` 手动移动文件就足够了。

> **注意** 这就是为什么我们需要将 FILES 添加到打算安装的头文件集中的原因。CMake 需要在安装其关联目标时能够定位这些文件。
>
> CMake 将基于目标的安装分为各种产物类型。可用产物类型（在 CMake 3.23 中）为：
>
> - **ARCHIVE**：静态库（.a / .lib）、DLL 导入库（.lib）和一些其他"归档类似"的对象。
> - **LIBRARY**：共享库（.so）、模块和其他动态可加载对象。不包括 Windows 的 DLL 文件（.dll）或 MacOS 框架。
> - **RUNTIME**：所有类型的可执行文件（除了 MacOS bundle）；以及 Windows 的 DLL（.dll）。
> - **OBJECT**：来自 OBJECT 库的对象。
> - **FRAMEWORK**：静态和共享 MacOS 框架。
> - **BUNDLE**：MacOS bundle 可执行文件。
> - **PUBLIC_HEADER / PRIVATE_HEADER / RESOURCE**：由 PUBLIC_HEADER、PRIVATE_HEADER 和 RESOURCE 目标属性描述的文件，通常与 MacOS 框架一起使用。
> - **FILE_SET `set-name`**：与目标关联的文件集。这是安装头文件的典型方式。
>
> 最重要的产物类型有已知的目标，除非另有指示，否则 CMake 将使用这些目标作为默认值。例如，RUNTIME 将安装到由 CMAKE_INSTALL_BINDIR 命名的位置，如果该变量可用，否则默认到 bin。
>
> 就像我们使用 cmake -B 来控制 CMake 将使用的构建目录一样，我们有多种选项来告知 CMake 安装位置。此位置通常称为安装前缀。要在配置时设置此位置，以便使用该构建树执行的每个 cmake --install 都默认为给定前缀，我们可以使用以下任一方法：
>
> - cmake --install-prefix 选项；
> - CMake 预设中的 installDir 字段；或
> - CMAKE_INSTALL_PREFIX 变量。
>
> **注意** 我们不建议在项目内设置 CMAKE_ 变量。在没有任何充分理由的情况下设置 CMAKE_INSTALL_PREFIX 尤其是不好的做法，因为它阻止用户覆盖它。在提供默认值时，项目应检查 CMAKE_INSTALL_PREFIX_INITIALIZED_TO_DEFAULT。
>
> 或者，我们可以使用 cmake --install --prefix 选项来设置单次安装调用的安装前缀。
>
> 产物类型默认目标完整列表如下表所示：
>
> | 目标类型 | 变量 | 内置默认 |
> |----------|------|----------|
> | RUNTIME | ${CMAKE_INSTALL_BINDIR} | bin |
> | LIBRARY | ${CMAKE_INSTALL_LIBDIR} | lib |
> | ARCHIVE | ${CMAKE_INSTALL_LIBDIR} | lib |
> | PRIVATE_HEADER | ${CMAKE_INSTALL_INCLUDEDIR} | include |
> | PUBLIC_HEADER | ${CMAKE_INSTALL_INCLUDEDIR} | include |
> | FILE_SET (type HEADERS) | ${CMAKE_INSTALL_INCLUDEDIR} | include |
>
> 在大多数情况下，除非项目需要将产物安装到默认位置的特定子目录，否则项目应保留默认值。
>
> CMake 默认不定义 `CMAKE_INSTALL_<dir>` 变量。如果项目希望指定安装到这些位置之一的子目录中，则需要 include GNUInstallDirs 模块，该模块将为所有尚未定义的 `CMAKE_INSTALL_<dir>` 变量提供值。

## 练习 1 - 安装产物

对于现代基于目标的 CMake 项目，安装产物是微不足道的，只需要对 install(targets) 的一次调用。

```cmake
install(
  TARGETS MyApp MyLib

  FILE_SET HEADERS
  FILE_SET anotherHeaderFileSet
)

大多数产物类型默认安装，无需在 install() 命令中列出。但是，必须命名 FILE_SET 以让 CMake 知道你想安装。在上面的示例中，我们安装两个文件集，一个名为 HEADERS，另一个名为 anotherHeaderFileSet。

当命名时，产物类型可以接受各种选项，例如目标位置。

```cmake
include(GNUInstallDirs)

install(
  TARGETS MyApp MyLib

  RUNTIME
    DESTINATION ${CMAKE_INSTALL_BINDIR}/Subfolder

  FILE_SET HEADERS
)
```

这会将 MyApp 目标安装到 bin/Subfolder（如果打包者没有更改 CMAKE_INSTALL_BINDIR）。

重要的是，如果从未给出 OBJECT 产物类型的目标位置，它将表现得像 INTERFACE 库，只安装其头文件。

## 练习 2 - 导出目标

这堆已安装文件的原始集合是一个好的开始，但我们失去了 CMake 目标模型。这些实际上比我们已在步骤 4 中讨论的预编译供应商库好不到哪里去。我们需要一种方法让其他项目从我们在安装树中提供的重建我们的目标。

CMake 提供的解决此问题的机制是称为"目标导出文件"的 CMakeLang 文件。它由 `install(EXPORT)` 命令创建。

```cmake
install(
  TARGETS MyApp MyLib
  EXPORT MyProjectTargets
)

include(GNUInstallDirs)

install(
  EXPORT MyProjectTargets
  DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MyProject
  NAMESPACE MyProject::
)
```

上面的示例有几个部分。首先，install(TARGETS) 命令接受导出名称，基本上是要添加已安装目标的列表。

稍后，install(EXPORT) 命令使用此目标列表生成目标导出文件。这将是位于提供的 DESTINATION 中的名为 `<ExportName>.cmake` 的文件。此示例中提供的 DESTINATION 是传统的，但 find_package() 命令搜索的任何位置都有效。

最后，目标导出文件创建的目标将以 NAMESPACE 字符串为前缀，即它们的形式为 `<NAMESPACE><TargetName>`。约定是项目名称后跟两个冒号。

出于将在后续步骤中变得更明显的原因，我们通常不直接消费此文件。相反，我们有一个名为 `<ProjectName>Config.cmake` 的文件通过 include() 消费它。

```cmake
include(${CMAKE_CURRENT_LIST_DIR}/MyProjectTargets.cmake)
```

> **注意** CMAKE_CURRENT_LIST_DIR 变量命名当前运行的 CMake 语言文件所在的目录，无论该文件如何被包含或启动。
>
> 然后此文件与目标导出一起通过 install(FILES) 安装。

```cmake
install(
  FILES
    cmake/MyProjectConfig.cmake
  DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MyProject
)
```

> **注意** 此文件的名称及其位置由 find_package() 命令的发现语义决定，我们将在下一步中更多讨论。

## 练习 3 - 导出版本文件

当从目标导出文件导入 CMake 目标时，没有"退出"或"撤消"操作的方法。如果发现包是与请求的版本不兼容的错误版本，我们将被卡在在学习版本信息时产生的任何副作用上。

CMake 为此问题提供的答案是轻量级版本文件，仅描述此版本兼容性信息，可以在 CMake 承诺完全导入文件之前检查。

CMake 提供用于生成这些版本文件的辅助模块和脚本，即 CMakePackageConfigHelpers 模块。

```cmake
include(CMakePackageConfigHelpers)

write_basic_package_version_file(
  ${CMAKE_CURRENT_BINARY_DIR}/MyProjectConfigVersion.cmake
  COMPATIBILITY ExactVersion
)
```

可用版本为：

- AnyNewerVersion
- SameMajorVersion
- SameMinorVersion
- ExactVersion

此外，包可以标记自己为 ARCH_INDEPENDENT，适用于不附带任何绑定到特定机器架构的二进制文件的包。

默认情况下，write_basic_package_version_file() 使用的 VERSION 是分配给 project() 命令的 VERSION 参数。
