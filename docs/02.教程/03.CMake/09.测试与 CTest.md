# 步骤 8：测试与 CTest

历史上，测试不是构建系统的职责。最好它可能有一个特定目标映射到构建和运行项目的测试。

在 CMake 生态系统中，情况恰恰相反。CMake 的测试生态系统称为 CTest。这个生态系统既简单得令人误导，又极其强大。事实上，它如此强大，以至于值得为其撰写完整的教程来描述我们可以用其实现的一切。

这不是那个教程。在本节中，我们将粗略介绍 CTest 提供的一些功能。

## 背景

从核心来说，CTest 是一个任务启动器，它运行命令并报告它们是否返回零或非零值。这是我们与 CTest 打交道的层级。

CMake 通过 `enable_testing()` 和 `add_test()` 命令与 CTest 直接集成。这些命令允许 CMake 在构建文件夹中设置 CTest 发现和运行我们可能感兴趣的各种测试的必要基础设施。

在设置和构建测试后，调用 CTest 的最简单方法是直接在构建目录上运行它：

```bash
ctest --test-dir build

这将运行所有可用的测试。可以使用正则表达式运行特定测试。

```bash
ctest --test-dir build -R SpecificTest
```

CTest 还具有用于脚本、夹具、sanitizers、作业服务器、指标报告等的高级模式。更多信息请参阅 ctest(1) 手册。

## 练习 1 - 添加测试

CTest 约定规定构建和运行测试应基于名为 BUILD_TESTING 的默认开启变量。当通过 CTest 模块使用完整的 CTest 功能时，此 `option()` 会自动为我们设置。当使用更精简的测试方法时，期望项目自行设置该选项（或至少是类似名称的选项）。

当 BUILD_TESTING 为 true 时，应在根 CML 中调用 `enable_testing()` 命令。

```cmake
enable_testing()
```

这将在构建树中生成所有必要的元数据，供 CTest 查找和运行测试。

完成此操作后，可以使用 `add_test()` 命令在项目的任何位置创建测试。此命令的语义类似于 `add_custom_command()`；我们可以将可执行目标命名为"命令"。

```cmake
add_test(
  NAME MyAppWithTestFlag
  COMMAND MyApp --test
)
```
