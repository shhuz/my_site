# 步骤 6：深入系统自省

为了发现关于系统环境和工具链的信息，CMake 经常编译小型测试程序来验证编译器标志、头文件和内置函数或其他语言构造的可用性。

在本节中，我们将利用 CMake 在其自身项目代码中使用的相同测试程序机制。

## 背景

一个追溯到配置和构建系统最早时代的技巧是通过编译一个使用该功能的小型程序来验证某些功能的可用性。

CMake 在许多上下文中使这变得不必要。正如我们将在后续步骤中解决的问题，如果 CMake 能够找到库依赖项，我们可以依赖它具有我们期望的所有设施（头文件、代码生成器、测试实用程序等）。相反，如果 CMake 找不到依赖项，即使尝试使用该依赖项也几乎肯定会失败。

然而，还有一些关于工具链的其他类型信息，CMake 不能轻易传达。对于这些高级情况，我们可以编写自己的测试程序和编译命令来检查可用性。

CMake 提供模块来简化这些检查。这些在 cmake-modules(7) 中有文档说明。任何以 Check 开头的模块都是我们可以用来检查工具链和系统环境的系统自省模块。一些值得注意的包括：

- **CheckIncludeFiles**：检查一个或多个 C/C++ 头文件。
- **CheckCompilerFlag**：检查编译器是否支持给定标志。
- **CheckSourceCompiles**：检查源代码是否可以为给定语言构建。
- **CheckIPOSupported**：检查编译器是否支持过程间优化（IPO/LTO）。

## 练习 1 - 检查头文件

执行快速简单的检查是查看给定头文件在某个平台上是否可用，CMake 为此提供 CheckIncludeFiles。这最适合系统头和内置头文件，这些头文件可能尚未由特定包提供，但预计在大多数构建环境中可用。

```cmake
include(CheckIncludeFiles)
check_include_files(sys/socket.h HAVE_SYS_SOCKET_H LANGUAGE CXX)
```

> **注意** 这些函数在 CMake 中不是立即可用的，它们必须通过 include() 它们的关联模块（即 CMakeLang 文件）添加。许多模块位于 CMake 自己的 Modules 文件夹内。这个内置 Modules 文件夹是 CMake 在评估 include() 命令时搜索的位置之一。你可以将这些模块视为标准库头文件，它们应该是可用的。
>
> 一旦知道头文件存在，我们就可以使用已经覆盖的条件语句和目标命令机制将这些信息传达给我们的代码。

## 练习 2 - 检查源码是否可编译

有时仅仅检查头文件是不够的。这在没有头文件可供检查时尤其真实，例如编译器内置函数的情况。对于这些场景，我们有 CheckSourceCompiles。

```cmake
include(CheckSourceCompiles)
check_source_compiles(CXX
  "
    int main() {
      int a, b, c;
      __builtin_add_overflow(a, b, &c);
    }
  "
  HAS_CHECKED_ADDITION
)
```

> **注意** 默认情况下，CheckSourceCompiles 构建并链接一个可执行文件。要检查的代码必须提供有效的 int main() 才能成功。
>
> 执行检查后，此系统自省可以与我们讨论头文件的方式完全相同地应用。

## 练习 3 - 检查过程间优化

过程间和链接时优化可以为某些软件提供显著的性能改进。CMake 有能力通过 CheckIPOSupported 检查 IPO 标志的可用性。

```cmake
include(CheckIPOSupported)
check_ipo_supported() # 如果 IPO 不支持则为致命错误
set_target_properties(MyApp
  PROPERTIES
    INTERPROCEDURAL_OPTIMIZATION TRUE
)
```

> **注意** 关于项目内 IPO 配置有几个重要的注意事项：
>
> CMake 不知道每个编译器上的每个 IPO/LTO 标志，对于已知工具链的单独调优通常可以获得更好的结果。
>
> 在目标上设置 INTERPROCEDURAL_OPTIMIZATION 属性不会改变它链接的任何目标，或来自其他项目的依赖项。IPO 只能"看到"也适当编译的其他目标。
>
> 出于这些原因，认真考虑通过外部机制（预设、`-D` 标志、工具链文件等）在整个依赖树的所有项目中手动设置 IPO/LTO 标志，而不是在项目内控制。
>
> 然而，特别是对于非常大的项目，具有在项目内使用 IPO 的机制在任何可用时都非常有用。
