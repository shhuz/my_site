# 步骤 4：深入 CMake 目标命令

CMake 中有几个目标命令可用于描述需求。提醒一下，目标命令是修改其应用的目标属性的命令。这些属性描述了构建软件所需的要求，例如源文件、编译标志和输出名称；或消费目标所需的属性，例如头文件包含、库目录和链接规则。

> **注意** 如在步骤 1 中讨论的，构建目标所需的属性应使用 PRIVATE 作用域关键字描述，消费目标所需的属性使用 INTERFACE，两者都需要的属性使用 PUBLIC 描述。
>
> 在本节中，我们将介绍 CMake 中所有可用的目标命令。并非所有目标命令都是等同的。我们已经讨论过两个最重要的目标命令：`target_sources()` 和 `target_link_libraries()`。在剩余的命令中，有些与这两个几乎一样常用，有些有更高级的应用，而一些应仅在其他选项不可用时作为最后手段使用。

## 背景

在继续之前，让我们命名所有 CMake 目标命令。我们将它们分为三组：推荐的和一般有用的命令，高级的和需要谨慎使用的命令，以及"脚枪"命令（应避免使用的命令），除非必要。

| 常用/推荐 | 高级/需谨慎 | 生僻/脚枪 |
|-----------|-------------|-----------|
| target_compile_definitions() | get_target_property() | target_include_directories() |
| target_compile_features() | set_target_properties() | target_link_directories() |
| target_link_libraries() | target_compile_options() | |
| target_sources() | target_link_options() | |
| | target_precompile_headers() | |

> **注意** 不存在"糟糕"的 CMake 目标命令。它们都有有效的用例。此分类旨在为新手提供关于在解决问题时应该首先考虑哪些命令的简单直觉。
>
> 我们将在以下练习中演示其中大多数。我们不使用的三个命令是 `get_target_property()`、`set_target_properties()` 和 `target_precompile_headers()`，因此我们将在这里简要讨论它们的用途。

`get_target_property()` 和 `set_target_properties()` 命令通过名称直接访问目标的属性。它们甚至可用于将任意属性名称附加到目标。

```cmake
add_library(Example)
set_target_properties(Example
  PROPERTIES
    Key Value
    Hello World
)

get_target_property(KeyVar Example Key)
get_target_property(HelloVar Example Hello)

message("Key: ${KeyVar}")
message("Hello: ${HelloVar}")
```

```bash
cmake -B build
...
Key: Value
Hello: World
```

CMake 具有语义意义的所有目标属性的完整列表记录在 cmake-properties(7) 中，但这些大多应该使用它们的专用命令进行修改。例如，无需直接操作 LINK_LIBRARIES 和 INTERFACE_LINK_LIBRARIES，因为这些由 `target_link_libraries()` 处理。

相反，一些较少使用的属性仅通过这些命令可访问。DEPRECATION 属性（用于附加弃用通知到目标）只能通过 `set_target_properties()` 设置；类似地，ADDITIONAL_CLEAN_FILES 也是如此，用于描述要由 CMake 的 clean 目标移除的额外文件；以及其他此类属性。

`target_precompile_headers()` 命令接受头文件列表（类似于 target_sources()），并从它们创建预编译头文件。然后此预编译头文件被强制包含在目标中的所有翻译单元中。这对于构建性能可能有用。

## 练习 1 - 特性与定义

在前面的步骤中，我们警告不要全局设置 `CMAKE_<LANG>_STANDARD` 并覆盖打包者关于使用哪种语言标准的决定。另一方面，许多库需要最低要求的特性集才能构建，对于这些情况，使用 `target_compile_features()` 命令传达这些要求是合适的。

```cmake
target_compile_features(MyApp PRIVATE cxx_std_20)
```

`target_compile_features()` 命令将最低语言标准描述为目标属性。如果 `CMAKE_<LANG>_STANDARD` 高于此版本，或者编译器默认已提供此语言标准，则不采取任何操作。如果需要额外标志来启用标准，这些将由 CMake 添加。

> **注意** `target_compile_features()` 操作与其他目标命令相同类型的接口和非接口属性。这意味着可以继承使用 INTERFACE 或 PUBLIC 作用域关键字指定的语言标准需求。
>
> 如果语言特性仅在实现文件中使用，则相应的编译特性应为 PRIVATE。如果目标的头文件使用这些特性，则应使用 PUBLIC 或 INTERFACE。

对于 C++，编译特性的形式为 `cxx_std_YY`，其中 YY 是标准化年份，例如 14、17、20 等。

`target_compile_definitions()` 命令将编译定义描述为目标属性。它是向源代码本身传达构建配置信息的最常见机制。与所有属性一样，作用域关键字按我们讨论的那样适用。

```cmake
target_compile_definitions(MyLibrary
  PRIVATE
    MYLIBRARY_USE_EXPERIMENTAL_IMPLEMENTATION

  PUBLIC
    MYLIBRARY_EXCLUDE_DEPRECATED_FUNCTIONS
)
```

我们既不需要也不希望将 `-D` 前缀附加到使用 `target_compile_definitions()` 描述的编译定义。CMake 将确定当前编译器的正确标志。

## 练习 2 - 编译与链接选项

有时，我们需要对传递给编译和链接行的确切选项进行特定控制。这些情况由 `target_compile_options()` 和 `target_link_options()` 处理。

```cmake
target_compile_options(MyApp PRIVATE -Wall -Werror)
target_link_options(MyApp PRIVATE -T LinksScript.ld)
```

无条件调用 `target_compile_options()` 或 `target_link_options()` 有几个问题。主要问题是编译器标志特定于正在使用的编译器前端。为确保我们的项目支持多个编译器前端，我们必须只传递与编译器兼容的标志。

我们可以通过检查 `CMAKE_<LANG>_COMPILER_FRONTEND_VARIANT` 变量来实现这一点，该变量告诉我们编译器前端支持的标志样式。

> **注意** 在 CMake 3.26 之前，`CMAKE_<LANG>_COMPILER_FRONTEND_VARIANT` 仅针对具有多个前端变体的编译器设置。在 CMake 3.26 之后的版本中，仅检查此变量就足够了。
>
> 然而本教程针对 CMake 3.23。因此，逻辑比我们这里有时间讨论的更复杂。本教程步骤已包含在 CMake 3.23 上检查 MSVC、GCC、Clang 和 AppleClang 编译器变体的正确逻辑。

即使编译器接受我们传递的标志，编译器标志的语义也会随时间变化。这在警告方面尤其如此。项目不应默认启用警告作为错误的标志，因为这可能会破坏它们在后期版本中包含的看似无害的编译器警告上的构建。

> **注意** 对于错误和警告，考虑将标志放在 `CMAKE_<LANG>_FLAGS` 中用于本地开发构建和 CI 运行（通过预设或 `-D` 标志）。我们知道在这些上下文中使用的确切编译器和工具链，因此我们可以精确地定制行为而不会冒险在其他平台上破坏构建。

## 练习 3 - 包含与链接目录

> **注意** 本练习要求直接在命令行中使用编译器构建归档文件。它不在后续步骤中使用。仅用于演示 target_include_directories() 和 target_link_directories() 的用例。
>
> 如果由于任何原因无法完成本练习，可以将其视为仅信息性的，或完全跳过。

通常无需直接描述包含和链接目录，因为这些需求在链接 CMake 中生成的目标时或在从外部依赖导入 CMake 时继承（我们将在后面的步骤中涵盖的命令）。

如果我们碰巧有一些库或头文件不由我们需要引入构建的 CMake 目标描述，例如供应商提供的预编译二进制文件，我们可以使用 `target_link_directories()` 和 `target_include_directories()` 命令将其合并。

```cmake
target_link_directories(MyApp PRIVATE Vendor/lib)
target_include_directories(MyApp PRIVATE Vendor/include)
```

这些命令使用映射到 `-L` 和 `-I` 编译器标志（或编译器用于链接和包含目录的任何标志）的属性。

当然，传递链接目录并不会告诉编译器链接任何东西到构建中。为此我们需要 `target_link_libraries()`。当 `target_link_libraries()` 收到不映射到目标名称的参数时，它会将字符串直接添加到链接行作为要链接到构建的库（prepend 任何适当的标志，如 `-l`）。
